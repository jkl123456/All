# 直播间手写签名（沙画）

观众在弹幕里写一个名字，程序把这个名字**当场写成沙画签名**：整段名字被拆成一笔一笔的笔迹，
沙粒从一个会移动的笔尖里流出来，一笔一笔落在沙盘上，最后补一道收尾弧线。

**送礼物可以插队**：弹幕里写了名字、又送了礼物的人，直接排到队首，而且写的是**他在弹幕里写的那个名字**（不是他的昵称）。

```
抖音直播间
   │  弹幕 / 礼物
   ▼
┌──────────────┐   ┌────────────┐   ┌────────────────┐   ┌───────────────┐
│ 事件接入层    │──▶│ 排单队列    │──▶│ 签名笔迹生成    │──▶│ OBS 叠加层     │
│ mock/external│   │ 礼物插队    │   │ 楷体→骨架→笔顺 │   │ 沙粒笔触+笔尖  │
└──────────────┘   │ 昵称↔名字记忆│   │ 0.1 秒/单      │   │ 1080×1920     │
                   └────────────┘   └────────────────┘   └───────────────┘
```

## 快速开始

```bash
pip install -r requirements.txt          # fastapi / uvicorn / Pillow
python run.py                            # 默认 mock 数据源，不用直播间也能跑
```

日常开播直接**双击 `scripts/start_server.bat`** 就行（等价于 `python run.py`，
窗口留着别关；多带的参数会原样传给 run.py，比如 `start_server.bat --provider local`）。

打开 <http://127.0.0.1:8850/> 是直播叠加层，<http://127.0.0.1:8850/admin/> 是后台。

想手动来一单（调试最快的方式）：

```
http://127.0.0.1:8850/api/simulate?nickname=小明&name=张三丰
```

## 接真实抖音直播间

要**两个进程**，先起浏览器抓弹幕的桥，再起服务：

**房间号已经写在 `config.yaml` 里了**（`platform.external.room: "YOUR_ROOM_ID"`，
就是 <https://live.douyin.com/YOUR_ROOM_ID?camera_id=0> 这间），所以日常开播不用带参数：

```bash
# 1) 一次性：用你自己的抖音账号登录（会弹一个真浏览器，扫码登录，登录态存 .chrome-douyin/）
python scripts/douyin_browser.py --login

# 2) 抓弹幕，广播到 ws://127.0.0.1:9000（房间号自动取 config.yaml）
python scripts/douyin_browser.py

# 3) 另开一个窗口，服务从这个桥取事件（config.yaml 里 platform.type 已经是 external，也可以不带参数）
python run.py
```

换直播间有两种写法，等价：改 `config.yaml` 的 `platform.external.room`，
或者临时传参 `python scripts/douyin_browser.py https://live.douyin.com/123456789?camera_id=0`
（直接贴完整地址会自己抠出房间号，`?camera_id=0` 这类查询串会被丢掉）。

> **必须登录**。抖音匿名会话拉 `/webcast/im/fetch/` 会一直回 0 字节，页面上也会写「需先登录，才能开始聊天」。
> `--login` 用的是持久化 profile（`.chrome-douyin/`，约 116MB），登录一次之后 2) 直接就能抓。

### 为什么不走 WebSocket

老代码 `app/platforms/douyin.py` 里的握手 + protobuf 解帧逻辑是能用的，但**抖音网页端已经不再开 `webcast/im/push/v2` 这条 WebSocket**了。
实测在主 frame、所有 iframe、所有 worker、service worker 上挂 `Network.webSocketCreated`，一条都没有。
现在是 HTTP 长轮询 `GET /webcast/im/fetch/`，带 `a_bogus` 反爬签名，聊天消息由 **XMLHttpRequest**（不是 fetch）发出。

所以 `scripts/douyin_browser.py` 的路线是：用 CDP 打开真浏览器 → `Page.addScriptToEvaluateOnNewDocument` 包装
`XMLHttpRequest.prototype.open` → 把响应的 ArrayBuffer 转 base64 塞进 `window.__imFrames` → 通过 CDP 取出 →
交给 `app/platforms/douyin.py` 里现成的解帧/事件映射代码 → 广播给 `run.py`。

`app/platforms/base.py` 里 `douyin` 类型现在会直接报错，提示改用 `--source external`，就是怕有人再踩一遍这条死路。

### 排查

| 现象 | 原因 |
|---|---|
| 桥连上了但一条事件都没有 | 直播间没人说话，或没登录（匿名回 0 字节） |
| 页面停在「直播加载中」`readyState: 0` | 直播间本身没在推流（换新 profile 也一样），不是脚本的问题 |
| `[bridge] 已在 ws://127.0.0.1:9000 等 run.py 接入` 出现两次 | 端口被上一个没退干净的进程占着，先杀掉 |
| `ENOSPC` | C 盘满了。把 `TMP`/`TEMP` 指到别的盘，profile 用 `--profile` 指定 |

### 长时间挂机被抖音暂停

抖音直播间挂久了会弹一层「长时间无操作，已暂停播放 / 累计节能 N 分钟」，底下两个按钮：
**继续播放** 和 **使用客户端免弹窗**。一暂停，视频停、IM 轮询也停，弹幕就断了——
表现是直播间明明在聊，采集器一条都不来。

`KEEPALIVE_JS` 每 4 秒在页面里做三件事：

1. 没暂停时发一个合成 `mousemove`，把"无操作"的计时器按住，尽量不让它弹；
2. 弹了就点 **继续播放**；
3. 按钮点不到（遮罩换了、被别的层盖住）就退一步 `video.play()`。

三个坑，别改：

- **只认文字不认 class**。遮罩的 class 是哈希过的（`tp31AxZe` / `JL05k7eS`），每次发版都变，
  「继续播放」四个字不变。
- **必须用 `innerText` 全等匹配**，不能用"包含"。页面上还有「使用客户端免弹窗」，
  点到它会去唤起/下载客户端，直播间直接废掉。
- **别用 `querySelector('video').play()` 当主路径**。有些版本遮罩在，video 却不算 paused，
  `play()` 是空操作；反过来遮罩点了没反应时它才管用——所以是"先点按钮，再兜底 play()"。

成功时会打一行 `[bridge] 检测到暂停，已自动续播（click），累计 3 次`。

想看每一帧原始数据：加 `--debug`。想看着浏览器干活：加 `--show`。

## 名字是怎么认出来的

1. **弹幕内容整条就是名字**（`queue.prefix` 为空时）——过滤掉纯数字、纯符号、以及「主播好」这类客套话，剩下的 2~5 个汉字就当名字入队。
2. **昵称 → 名字记忆表**（后台能看到这张表）——任何一次被判为名字的弹幕都会记成「这个昵称写的名字」。
3. **礼物事件不认昵称**——礼物本身不带名字，所以送礼插队时去记忆表里取这个人之前写过的名字。取到了就写那个名字，取不到才退回用昵称。

这条规则是核对过的，`scripts/dev_bridge.py` 就是拿它做回归的：

```
18:56:48 @橘子汽水 弹幕「张三」入队
18:56:51 @晚安小羊 弹幕「李雷」入队
18:56:54 @橘子汽水 送 玫瑰(¥1) -> 插队写「张三」(取自弹幕里的名字)
18:56:55 @橘子汽水「张三」[礼签] 13 笔 / 3567.5px / 0.1s
```

排到队首也是**有礼貌的队首**：默认（`queue.gift_after_current: true`）**最新一次打赏永远插在
"当前正在写的那一单"的下一位**——后送的排前面，最新打赏最显眼。想改成"先送的先画"更公平，
把它设成 `false`，礼物之间就还是按先后顺序走。

## 名字审核（能不能写在公屏上）

直播是公开播出的，把观众的名字写成书法大字，等于替他在公屏上喊话。所以入队前先过一道审，
配置在 `config.yaml` 的 `moderation:`。

**两层，先便宜后贵**：

1. **本地黑名单**（`app/moderation.py` 的 `LOCAL_PATTERNS`，0ms，不发网络）：
   广告引流（加微信/vx/qq/网址）、赌博毒品枪支、直白色情、最常见的脏话变体。
   只收命中率高、几乎不误伤的词。
2. **deepseek-flash**（约 1~2 秒）：本地规则表达不了的语境——暴力威胁、擦边谐音、
   涉政敏感、民族地域歧视。提示词明确要求**不确定就放行**：误杀一个正常观众，
   比放过一个边缘词更伤直播。

实测：

```
@B 弹幕「干死你」拦下：暴力威胁辱骂              （AI，1.3s）
@C 弹幕「加微信abc」拦下：命中本地规则「加微信」   （本地，0ms）
@D 弹幕「李雷」入队                            （放行，1.3s）
```

几个要知道的点：

- **审核是入队前的网络调用，会占 1~2 秒**。弹幕连续涌入时会排队审，顺序不乱，但入队会滞后。
  本地规则命中的是 0ms，所以广告号挡得很快。
- **`deepseek-flash` 是推理模型**：它先写 `reasoning_content` 再给正文。`max_tokens` 给小了
  （第一版给了 60）推理就把额度吃光、`content` 返回空串 → 解析失败 → 全部 fail_open 放行。
  现在给 500，并做了宽容解析（剥 ```json 围栏、截 `{...}`）。
- **`fail_open: true`（默认）**：Key 失效 / 网络断 / 超时都**放行**并记一行警告。
  本地黑名单已经兜住硬违规，而"审核挂了导致整场名字都写不出来"是更大的事故。
  要严格就设 `false`，那时宁可少写一张。
- **后台 `/api/simulate` 和手动加单不过审**——那是你自己在调画面，不该被自己的规则挡住。
- 后台标题下面有一行实时状态：`审核：deepseek-flash · 已问 N 次 · 拦截 M · 失败 K`，
  失败数一直涨就说明 Key 或网络有问题。

## 祝福语音（写完一个字，念一句给他）

每写一个名字，配一句专属祝福：**运笔开始那一刻开口，写完那一刻收声**，
字幕挂在名字上方。配置在 `config.yaml` 的 `voice:`，代码在 `app/voice.py`。

```
名字 + 档位 → 文案（默认从固定模板里轮播取一句 ; 可切 AI 现写）
            → 合成音频（edge-tts ; 连不上退回 Windows SAPI）
            → ffprobe / wave 量出真实时长
            → payload 带 voice_url / voice_ms / voice_text
            → overlay 在 draw_start 里播，写完 stopVoice
```

### 为什么一定要量时长

`voice.fit_duration()` 把运笔时长对齐到这句语音：

```
运笔 = max(档位时长, 语音时长 + 0.25s)，上限 20s
```

语音比字短（4 秒的话配 13 秒的尊签）就**不动**——字慢慢写更贵重；
语音比字长就把字写慢一点。不这么对齐的话，观众看到的永远是"字写完了还在念，
而且念到一半画面已经切下一位"。上限 20 秒是防 AI 写长句把队列拖积压。

### 文案：10 条模板轮播，0 token

现在的默认方案是**一次性生成、之后永久固定**：

- `scripts/gen_voice_texts.py` 调一次 deepseek，生成 **10 条普通 + 5 条送礼**模板，
  每句带一个 `{n}` 占位符，写完落到 `config.yaml` 的 `voice.templates` /
  `gift_templates`，同时把 `source` 改成 `template`。
  一次性成本约 1800 token，之后**每个名字都是 0 token**。
  想换一批：`python scripts/gen_voice_texts.py --apply`；只改个别字就直接编辑配置。
- **`pick: rotate`（默认）**：按顺序轮播。10 句里相邻两个观众一定不重句——
  按 md5 定死（`stable`）在只有 10 句时很容易撞车，两个人的祝福一模一样，听着很假。
- 生成脚本会做质检：`{n}` 必须在开头且只出现一次、后面必须跟中文逗号（否则 TTS 会
  把「张三愿你…」连读成一句）、句末之外至少两个分句逗号、不许带引号括号表情。
- 仍可切回 AI：`source: ai` + `voice.ai.model`。注意 `deepseek-flash` 是**推理模型**，
  它先吐 reasoning 再吐正文，`max_tokens` 给太小（比如 300）会被思考链吃光，
  正文变空串、钱照扣——实测 300 就是 0 字 514 token。要给至少 900。
- 文案落盘在 `data/voice/texts.json`（最多 800 条），重启不重问；
  音频按 `voice|rate|volume|text` 哈希落盘，同一句重播 0 成本。

### 两条引擎，为什么必须有第二条

| 引擎 | 音质 | 代价 | 什么时候用 |
|---|---|---|---|
| edge-tts（`zh-CN-XiaoxiaoNeural`） | 最好，像真人 | 要连 `speech.platform.bing.com` | `engine: auto` 的首选 |
| Windows SAPI（Huihui） | 一般，一听就是机器 | 完全离线，0.5~1 秒 | edge 连不上时自动接手 |

**国内网络直连 bing 的语音接口经常被 RST**（实测：DNS 正常、TCP 直接被拒），
所以只有 edge-tts 一条路的话，这个功能在国内基本等于没有。现在的策略：

- `engine: auto` 先试 edge，失败就当场走 `app/sapi_say.ps1`（PowerShell + COM，不装任何 Python 包）；
- edge 连续失败 3 次后冷却 10 分钟，期间不再白等连接超时，到点自动再试一次；
- 有梯子就把 `voice.proxy` 填上（如 `http://127.0.0.1:7890`）。
  **edge-tts 内部 `ws_connect(proxy=None)` 会盖掉系统代理**，所以环境变量里的
  `https_proxy` 对它无效，必须在配置里显式写。
- `sapi_say.ps1` 必须保持**纯 ASCII**：Windows PowerShell 5.1 按 ANSI 读无 BOM 的 .ps1，
  中文注释会被读成乱码，连带把 `param()` 那行吃掉、参数全部绑不上。

### 不拖累直播的四道保险

1. **在出图那一批里并发做**（`_ready_many`）：5 个人各 2 秒，串行就是 10 秒空场。
2. **单句最多等 12 秒**（`max_wait`）：超时就先播，这一单没声音。
3. **合成失败只是没声音**：`say()` 返回 `None`，payload 里就没有 `voice_url`，写字流程一点不受影响。
4. **开播预热**：`voice.warmup()` 真跑一次 edge。

### 为什么会出现「这一单没念」（踩过两次，都是这两条）

**① 预热是假的。** 原来的 `warmup()` 跟着 `engine: auto` 走，只要 `data/voice`
里有一个陈旧的 `你好.wav`（上一次 edge 连不上时 SAPI 兜底留下的），`_render`
就直接命中缓存、**0 秒返回**，edge 一次都没碰。于是"预热完成"变成了安慰剂，
第一位真实观众才是那个付出 8 秒冷启动代价的人——实测就是这么哑掉一单的。

现在 warmup 做了两件事：**强制 `engine: edge`**、**key 里带时间戳**（每次都是
新文件，不可能命中旧缓存），探测完把文件删掉。预热要 8 秒左右，日志里能看到
`预热完成 8.4s，引擎 mp3`——看到 `wav` 就说明 edge 这场没通。

**② 网络抖一下就整句放弃。** edge 正常 2~3 秒，但实测有过 9.3 秒的。
`hedge_after: 7` 的意思是：7 秒还没结果，就**同时**叫 SAPI（离线 0.7 秒）并肩跑，
谁先好谁用。代价是那一句音色变了，好处是再也不会整句没声音。

同时补了一个隐蔽的坑：edge-tts 是边收边写的，连接中途断掉会留下一个
**能打开但内容是断的** mp3。以前失败只把变量置空、不删文件，下次 `_render`
见文件存在就当缓存，播半句就没了。现在失败一律 `unlink`，并且用 1KB 下限
而不是"存在即有效"来判缓存。

### 后台与接口

后台「祝福语音」那一块可以实时改：开关、音色、语速、文案来源（AI/模板），
改完下一单生效并写回 `config.yaml`（保留注释）。「试听」会现写现念一句。

| 路径 | 用途 |
|---|---|
| `GET /api/voice` | 当前配置 + 音色列表 + 已合成句数 |
| `POST /api/voice` | `{enabled, voice, rate, source}` 切换（写回 config.yaml） |
| `GET /api/voice/preview?name=张三` | 试听：现写现念，返回音频地址和文案 |

**OBS**：浏览器源属性里勾上「控制音频」，否则声音只在这个页面里响，不进直播混音。

**抖音直播伴侣**（没有浏览器源，也没有系统声音采集）：双击 `scripts/overlay_window.bat`
开一个 1080×1920 的无边框 Chrome 窗口 → 直播伴侣「添加素材 → 窗口捕获」选它 → 铺满画布。

`overlay_window.bat` 的行为：已经开着同名窗口就不开第二个，只把它切到前台（避免两个窗口
同坐标叠在一起、看起来像"双击没反应"）；想强行再开一个用 `overlay_window.bat 8850 force`。
启动记录写在 `%TEMP%\zhibo-sign-overlay.log`。

> 这两个 `.bat` 必须保持 **CRLF 换行 + 纯 ASCII**。存成 LF 或写中文注释后，cmd 会把那行
> 很长的 `start` 解析歪，表现就是**黑窗口一闪而过、不出窗口、也没有任何报错**。
> 同理 `app/sapi_say.ps1` 只能写 ASCII（PS 5.1 按 ANSI 读无 BOM 的脚本）。
声音要单独接：直播伴侣只采麦克风，得先启用声卡的「立体声混音」并选为麦克风
（控制面板 → 声音 → 录制 → 右键显示禁用设备），系统播放的声音才会进直播。

## 生成方式：local / sdcn / doubao / ai

```yaml
signature:
  provider: sdcn     # local | sdcn | doubao | ai
```

- **local**：PIL 渲染整串名字 → 二值化 → 骨架细化（Zhang-Suen，numpy 手写，不依赖 scikit-image）→ 沿方向连续性追踪成路径 → 按长度过滤 → 逐笔排序。0.1~0.3 秒一张，免费。**它是永远可用的兜底，别把它当"低配"**：观感上一半的差距来自笔顺和笔宽，那两条已经在 `signature.py` 里补齐了（见下）。
- **sdcn（推荐主力）**：**字体定字形，本地扩散模型上质感**。字体渲染出白底黑字 → 本地 SD1.5 **img2img** 低强度重描成毛笔字 → 抠成透明笔迹 → 贴底板 → 交给 `brush.py` 反推笔顺。一人一张约 2~4 秒，**完全离线、没有额度**。推理跑在独立进程 `scripts/sdcn_server.py`，主程序只做 HTTP 调用。
- **ai**：调火山方舟出「沙画签名」成图，然后整张渐显。约 20 秒一张，按张计费，要填 `api_key`。
- **doubao**：走 `.chrome-doubao/` 里的登录态，把 `overlay/assets/poster.jpg` 传上去，让它**只把图上的「智纪元」三个字换成观众的名字**，再把字抠成透明笔迹盖在擦过字的底板上（`postercut.py`）。约 25~40 秒一张。**网页版现在有额度/付费墙，随时可能不出图，别当主路径。**

**失败一律退回 local**，直播不会开天窗。

### 为什么 sdcn 不让模型"写字"

名字写错就是直播事故（「何小英」写成「何小瑛」），而扩散模型恰恰不擅长写准汉字。所以分工反过来：
**结构由字体保证（100% 正确），模型只改浓淡、飞白、笔锋毛边**。做法是 SD1.5 的 **img2img**：
初始图就是字体渲染出的白底黑字，`strength` 压在 0.35~0.5，结构几乎原样保留，模型只能动边缘。
这也是为什么一人一张、绝不拼竖排——SD1.5 在长图上会重复/崩坏字形，让它一次写 5 行是主动请它出错。

> 原计划是 ControlNet(lineart) 把线稿钉死，但部署时发现这台机器 `hf-mirror` / `huggingface.co`
> 都被代理掐了 SSL，权重只能走魔搭；而魔搭上没有 `control_v11p_sd15_lineart` 和 LCM LoRA，
> 只有 SD1.5 本体。img2img 从"这张图"开始改，比"让模型别乱画"更直接，还省 1.4G 下载和显存。

### 装 sdcn（一次性，约 4.3GB 权重）

推理要用 torch，**故意不装进主程序的环境**（主程序 10 个包就能跑，模型挂了不该影响直播）。
下面是**这台机器上实际跑通的**那套（2026-11 验证）：

```bash
# 1) venv 继承 base 里的 CUDA torch（base 已有 torch 2.3.0+cu121，别再装一遍）
python -m venv --system-site-packages H:/envs/sdcn

# 2) 只补 transformers / accelerate（官方源 SSL 会断，走清华镜像）
H:/envs/sdcn/Scripts/python.exe -m pip install -i https://pypi.tuna.tsinghua.edu.cn/simple \
    -U "transformers>=4.44,<5" accelerate safetensors

# 3) 权重走魔搭
python scripts/fetch_models.py

# 4) 起服务（冷启动约 160 秒，之后每次重启都要重读 4GB，固定这么久）
H:/envs/sdcn/Scripts/python.exe scripts/sdcn_server.py
```

日常更省事：双击 `scripts/start_sdcn.bat`（就是上面那句 + 一个不会闪退的窗口）。

> 它**先把端口查一遍再加载模型**。否则撞端口时要先白等两三分钟（4GB 权重读完）才报
> `Errno 10048`——第一次踩就是这么浪费的。端口上已经有服务时它会直接告诉你
> "已经有一个在跑，直接用"，2 秒退出，不会再烧 200 秒。

五个坑，全都是真踩出来的：

1. **别 `pip install torch`**。PyPI 现在给的是 `2.15.0+cpu`（126MB），装进 venv 会把 base 的
   CUDA 版**遮蔽掉**，`cuda.is_available()` 直接变 False。要么用 `--system-site-packages`
   继承 base，要么想办法拿到真正的 cu12x 轮子。
2. **`download.pytorch.org` 和 `files.pythonhosted.org` 在这台机器上被代理掐了 SSL**
   （`UNEXPECTED_EOF_WHILE_READING`）。pypi.org 的 metadata 能取，但大文件下载会卡死 ——
   清华镜像正常。
3. **必须 `USE_TF=0`**（`sdcn_server.py` 里已经 `setdefault` 好了）。base 里装着
   tensorflow 2.16（按 numpy 1.x 编译），而 numpy 是 2.5；transformers 只要探测到
   "TF 可用"就会去 import 它，然后炸在 `numpy.core.umath failed to import`。
   别去降 base 的 numpy —— 那会带崩 akshare / pandas / cv2。
4. **权重别指望 huggingface**，`hf-mirror.com` 和 `huggingface.co` 都连不上。
   `scripts/fetch_models.py` 走魔搭 API 直连，只拉 diffusers 需要的 safetensors，
   并顺手把 `safety_checker` 从 `model_index.json` 里摘掉（省 1.2G 冤枉下载）。
5. **魔搭上没有 ControlNet 和 LCM LoRA**，只有 SD1.5 本体——所以最终选了 img2img。

### 实测性能（RTX 3060 12GB）

| 场景 | 豆包网页版 | sdcn 本地 |
|---|---|---|
| 1 个名字 | 21~31 秒 | **2~3 秒** |
| 5 个名字一批 | 20~35 秒（还要等配额） | **12.9 秒** |
| 额度 | 有付费墙 | 无限制 |

调参都在 `config.yaml` 的 `signature.sdcn`，**最该动的是 `strength`**：
0.35 只把字体边缘磨成毛笔边（最安全）／**0.55 笔画明显变粗、有飞白干笔（当前默认）**／
0.65 往上模型开始自己加印章和落款小字（客户端有过滤兜底，但别贪）。
`steps` 是 DPM++ 步数，乘上 strength 才是实际 UNet 次数（16 × 0.55 ≈ 8 次）。

### 抠图时那两道"模型不听话"的兜底

strength 一高，SD 就不太守规矩。`app/pipeline/sdcn.py` 的 `_tight_cut` 里有三层处理，
**别删**：

1. **去彩色像素**：它会盖红印章、描朱文。墨的饱和度低、印章的高，按 S>70 一刀切掉，
   比在提示词里求它可靠。
2. **去孤立小连通块**：它会写落款小字。按面积比例掐掉（阈值 2.5%，笔画的"点"不会误伤）。
3. **用字体掩膜把笔画内部填实**（最关键）：SD 在 0.55 强度下会把笔画画成"浮雕"——
   笔画中间一道高光，而抠图拿亮度当 alpha，于是笔画内部被啃出一条条白缝，
   贴上去像被水洗过。字体图知道"这里本该是实心墨"，把它往里收两像素并进 alpha：
   **内部实心，边缘还是模型的毛刺**。
4. **上色 + gamma**：模型给黑墨，海报上是墨绿 `#06544a`。直接换色会让灰渐变边变浅绿、
   整幅字发虚，所以先把 alpha 抬一下（`a**0.75`）再染色。

### 字形与材质（决定"好不好看"）

两件事分开管，都能在**后台「签名样式」面板里当场切**（`POST /api/style`，下一单生效，
同时写回 `config.yaml`，重开还在）：

**字形**（`signature.sdcn.font`）——只影响 sdcn 这条路的初始图。字体在 `overlay/assets/fonts/`：

| 字体 | 观感 | 适合 |
|---|---|---|
| `MaShanZheng.ttf` 马善政毛笔楷书 | 笔锋重、有飞白，最像"写"的 | **默认，推荐** |
| `ZCOOLQingKeHuangYou.ttf` 站酷庆科黄油 | 粗黑、潮牌 logo 感 | 配立体挤出最像 3D |
| `ZhiMangXing.ttf` 志莽行书 | 连笔、最艺术 | 个别字会糊（实测「英」认不清），做名字有风险 |
| `LiuJianMaoCao` / `LongCang` / `ZCOOLKuaiLe` / `ZCOOLXiaoWei` | 草书 / 手写 / 圆胖 / 清秀 | 备选 |
| 空 = 系统楷体 | 最朴素 | local 兜底那条路**只能**用它 |

> ⚠️ local 那条路（骨架提笔画）必须用楷体：行书的连笔二值化后粘成一团，
> 提不出笔顺。所以字体只对 sdcn 生效；sdcn 挂了退回 local 时字会变回楷体，但不会报错。

字体是 Google Fonts 的（免费商用），`fonts.googleapis.com` 用普通 UA 会直接给**完整 TTF**，
不是切片 woff2——所以一行 httpx 就能下，不需要翻墙。

**材质**（`signature.sdcn.style`）——见 `app/pipeline/glyphstyle.py`，输入输出都是透明笔迹 PNG：

| style | 效果 | 说明 |
|---|---|---|
| `ink` | 墨绿平涂 | 和海报最协调，最稳 |
| `gold` | 烫金立体 | 金色渐变 + 斜向高光带 + 投影，最贵气 ← **现在默认** |
| `extrude` | 立体挤出 | 往右下拖出有厚度的块 + **切口高光**，最 3D |
| `emboss` | 立体浮雕 | 左上打光、右下沉，比平涂有层次但克制 |
| `chrome` / `neon` | 镀铬 / 霓虹 | 霓虹要深色背景才好看，浅底会糊 |

为什么材质不用模型画：立体/金属/发光本质是 **alpha 通道上的光照模拟**，
numpy 算一张只要 40~110ms，而且**每个名字的质感完全一致**。交给 SD 的后果是
第一个人的字是浮雕、第二个变水彩、第三个糊了——观众会以为设备坏了。

两个隐蔽的坑：

1. **挤出厚度必须跟字高走**（`depth=0` 自动 ≈ 字高 6%）。细笔画的字体用固定 16px
   会糊成一坨脏影子，粗字又不够厚。
2. **笔顺反推要用"没上材质"的那张图**（`art["trace"]`）。投影和挤出侧面的半透明像素
   alpha 能到 115，而 `brush.writes_for` 的阈值是 90——会多认出一笔"影子"，
   毛笔就会跑出字外照着影子描。

### 笔顺：从"猜"换成"查"

几何猜笔顺永远猜不对——「田」会绕外框一圈、「火」会先点旁点、「口」会一笔画完。
现在接入了**真实笔顺数据**（`app/pipeline/hanzi.py`）：

| | 用在哪 | 做法 |
|---|---|---|
| **local（自己画字）** | `signature.render` | 直接把标准中线当运笔轨迹。笔数、笔序、起笔方向全部正确，不会出现"一笔被切成两截" |
| **AI 成图（sdcn/豆包/素材库）** | `brush.py` | 轨迹仍从成图提（否则写完渐显的字和笔走过的地方对不上），改用**书写时间场**排顺序 |

时间场的思路：标准中线上每个点都带一个"书写时间"（第几笔 + 这笔走到哪），
每段骨架取它上面各点最近标准点的时间中位数，按时间排序。**笔画数不必相等**——
实测「李」被骨架切成 8 段（真 7 笔）也能排对，这是逐段一对一配对做不到的。

两个坑，都踩过：

- 这份数据的 **y 轴向上为正**，图像坐标向下。不翻转整个字会上下镜像——「李」的底部横被当成第一笔。
- 对齐要用**字格**（列切分 + 该格墨迹上下界），不能用笔画的包围盒：书法字的长撇会甩出字格，包围盒被撑大后标准字形整体错位。

数据从 `unpkg.com/hanzi-writer-data`（Make Me a Hanzi，Arphic 许可，可商用）按字取，
每字约 2KB，存 `data/strokes/{字}.json`，**拿到一次就永久离线**。
第一个字要联网（约 1.4 秒），所以：

```bash
python scripts/fetch_strokes.py          # 预下载 百家姓 + 常用字（约 2000 字，8MB）
python scripts/fetch_strokes.py --check  # 看已经缓存了多少字
```

服务端在出图的同时会**并发预取**这批字（fire-and-forget），出图 2~4 秒足够抓完，
不会拖慢排队。断网/取不到就自动退回几何排序，不会停播。

开关：`config.signature.stroke_order`（默认 `true`）。想复现"改之前"的样子就设 `false`。

验收工具（改完算法跑一下，肉眼确认）：

```bash
python scripts/check_stroke_order.py 李雷         # 每笔一条彩线，起笔处标序号
python scripts/check_stroke_order.py 李雷 --old   # 和旧算法对比
```

### local 这条路的笔宽

每一笔都带一条逐点宽度轮廓（`wps`）：落笔顿一下 → 中段最实 → 收笔收成尖，
一笔之内自带粗细节奏。开关是 `config.signature.taper`，关掉就能看到"改之前"的样子。

### 模板改字这条路的两个前提

1. **必须上传原图再让它改**。纯文生图它每次都重画整张海报，海鸥位置、印章、标语全会变。
2. **提示词要直接点名字**，写「把画面中间那几个大字换掉」它会自己找哪里像大字，偶尔改到标语上；写「图上的「智纪元」三个字」才稳。提示词在 `doubaoweb.EDIT_PROMPT`，`config.signature.doubao.edit_prompt` 可以覆盖。

### 三个踩过的坑，别再改回去

1. **字体必须是楷体（simkai.ttf），不能用行楷（STXINGKA.TTF）**。行楷的连笔太粗，二值化之后整块粘连，骨架出来是一团没法认的黑疙瘩。楷体笔画独立，骨架拓扑干净。
2. **必须先整串渲染、再按每个字的步进宽度切片**。早期是逐字渲染、逐字裁到墨迹外框，结果「一」和「张」被拉成一样高，基线全乱。现在 `_layout()` 用 `draw.text()` 一次画整串（保留基线），记下每个字的 x 起点再切，高度是统一的。
3. **骨架上的交叉点不能停**。原版 `_trace()` 一遇到度数 > 2 的节点就截断，汉字每一笔交叉都被切碎，笔画数掉到个位数（日志里出现过「提不出足够笔画（0）」）。现在 `trace_paths()` 在岔路口按**方向连续性**（夹角最小的邻居）往下走，一个字的笔顺才连得起来。

## 一批名字：一次豆包，回来切 N 份

豆包一张要 20~30 秒，队列里 5 个人逐个写就是两分钟。所以改成**一次问、一次出图**，
而且**按 20 秒一拍**去取单：

1. producer **每 `queue.gen_every`（默认 20）秒**才去队列取一次单，取的是队首最多
   `doubao.batch`（默认 5）个**真人单**（`qm.pop_real`），演示数据/空场幽灵单一律不混进来。
   **队列里没有真人名字就一拍都不打**——空场只播素材库，不叫 AI、不烧额度。
   空闲很久之后的第一个名字不用干等 20 秒，立刻开工；之后每批之间隔 20 秒，
   这 20 秒里陆续进来的名字正好攒成下一批。
2. **沿用同一个豆包会话**，但每批都重新上传一次模板图 `word_template.jpg`（会话长了上下文里那张图未必还在）。
3. 提示词分两套：
   - **多个名字**（`BATCH_PROMPT`）：参考模板的字，**竖版 1080×1920**，一个名字占一行共 N 行，
     从上到下依次是这 N 个名字。**别写"横排/居中"**——模型会把"横排"读成"整张图横着一行"。
   - **只有一个名字**（`SINGLE_PROMPT`）：就一句
     "模仿这张图上的文字，把文字替换为「名字」，生成一张图片，笔触、颜色、粗细和原图一致，
     背景风格保持一致"。短提示词在单人场景更稳：说"排成 1 行"模型反而会自己加排版，
     说"替换"它就当改字，笔迹跟着模板走。
4. 回来的整图存 `data/cache/sheets/`，`wordsheet.split` 按行切（先看宽高比判断模型到底竖排还是横排，
   两种都认；切点找"期望位置附近最宽的那条缝"，且必须单调递增，避免同一条缝切两刀切出空片）。
   单人的图整块当一个字处理，不用切。
5. 每份透明笔迹用 `wordsheet.place_box` 等比摆进背景中间留白（`place: cx/cy/max_w/max_h`），
   `wordsheet.compose` 出 `_full.jpg`，一人一份。

实测：5 个名字一批 25 秒左右，成图 1152×2048 竖版、五行分明，切开后每份只含自己那两三个字；
单个名字 25 秒，短提示词出来是白底一行「张三」，深墨绿毛笔，切图与合成位置都正常。

**浏览器不主动关**：代码里没有任何 `terminate`/`kill`，`_ensure_page` 用
`DETACHED_PROCESS` 启动，批次结束只断开 CDP 连接。窗口只在宿主进程（`run.py` / 调试脚本）
退出时才会消失——调试脚本一结束浏览器就被回收，别把它当成"生成没完就关了"。
另外桥接层已加：连接一断，所有挂着的 CDP 调用立刻抛错（而不是各等 120 秒超时），
这一批人马上退回本地笔画，不会卡住队列。

## 实时时钟（右下角）

画面右下角有一个「红点 + 时:分:秒 + 日期」的小胶囊，每 250ms 校一次。
它跟着真人小窗走：小窗在右下它就顶在小窗上方，切到左下它也跟过去。

它不是为了好看。抖音判「录播 / 挂机」看的是**实时性**：画面帧是不是现在生成的、
有没有周期性重复。一张静态海报 + 一轮一轮循环的成图，是这套判定里最省事的特征。
一个每秒都在跳的钟，等于持续给机审一个"这一帧是现在算出来的"的信号，成本最低。

两个实现细节：

* 用 250ms 而不是 1000ms —— 定时器本身有抖动，1 秒一校对的时候偶尔会让某一位数字
  晚 200ms 才跳，看起来像卡了一下。
* 窗口被遮挡/最小化时 Chrome 会把定时器节流到 1 次/分钟（画面就"停"了）。
  `run.py::open_window` 的启动参数里已经带了 `--disable-background-timer-throttling`
  和 `--disable-renderer-backgrounding`，别删。

只放时间，不放"在线人数"——人数是编的，编错了比没有更假。

开了真人小窗时，时钟会被顶到小窗上方（`draw.js::camPlace()` 直接写 `hud.style.bottom`）。
这里**故意不加 transition**：过渡动画在虚拟时间/窗口不可见的场景下会停在起始帧，
表现就是时钟永远压在小窗里面。跳一下比错位好。

## 真人出镜小窗（右下角）

> 后台 →「真人出镜小窗」→ 上传视频，立刻贴在画面**右下角**（可切左下）。

平台判「录播 / 挂机」看的是**画面里有没有会动的人**。时钟和背景轮换只能把
"机械重复"拆散，真正管用的是画面里有一张会动的脸。这一段就是补这个。

### 硬规矩（代码里写死，别改）

| 规矩 | 原因 |
|---|---|
| 必须 `muted` | Chrome 只给静音视频自动播放的许可。不静音 = 整块黑，比没有更糟 |
| 多段**挨个播**，不 loop | 同一段反复循环本身就是"周期性重复"，和整屏循环一个毛病 |
| 非 H.264 必须转码 | 手机/剪映导出的竖屏视频大量是 HEVC，CEF 解不了，**而且不报错**，就是一个黑方块 |

### 为什么是右下角

左下角被「全力以赴 未来可期」（y≈1265~1345）占着，小窗想放大就会压主标语；
右下角只有一行「心有山海 静而不争」（y≈1490~1520），压到它的右端比压住主标语容易接受，
而且右边是整块深绿山体，画面干净。

### 尺寸是算出来的，不是拍的

小窗底边 58 + 高 H + 间隙 16 + 时钟 44，不能碰到那行装饰字（y≈1490）。
所以 H 默认 **340**，`480×600` 的竖屏视频落到 **272×340**；
`440×340` 是"最大宽 / 最大高"，JS 按视频真实比例内接，不拉伸。

想调大就去后台改，但**改完先看画面**。这块地就这么高，不是配置没生效。

### 编码：HEVC 是个坑

上传时会扫 mp4 的 `stsd` fourcc：

* `avc1` / `avc3` → H.264，直接用
* `hvc1` / `hev1` → HEVC，**先转码**：`ffmpeg -c:v libx264 -preset veryfast -crf 26 -an`
  （去音轨，页面里本来就静音播；降到 720 高，小窗只有两三百像素宽）
* `av01` / `vp09` → 直接用

ffmpeg 路径找三处：`config.yaml` 的 `cam.ffmpeg` → PATH → 几个常见安装目录。
一个都找不到就原样存下来，后台会标一条橙色说明——不丢文件，但那个黑方块会一直在。

已经传进来的 HEVC 不用重传，后台点「**转码旧视频**」（`POST /api/cam/fix`）就地转。

### 接口

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/cam` | 列表 + 当前 + 显示参数 |
| POST | `/api/cam/add` | 上传，body 是视频原文件（≤200MB，只认 mp4/webm/mov），非 H.264 自动转码 |
| POST | `/api/cam/pick` | `{id}` 切成当前这段 |
| POST | `/api/cam/remove` | `{id}` 删除 |
| POST | `/api/cam/fix` | 把库里非 H.264 的段转一遍（给老数据补的） |
| POST | `/api/cam/opt` | `{on,pos,w,h,x,y,k,mirror}` 开关 / 位置（bl·br）/ 最大宽高 / 边距 / 圆角 / 镜像 |

`pos=br` 时 `x` 是"离右边多远"，`bl` 时是"离左边多远"。时钟永远跟着小窗同一边、
顶在它上方 16px。

存 `overlay/assets/cam/`，索引 `_cam.json`（`{items, cur, opt}`，和背景库的裸 list 不是一套结构）。
上传后广播 `cam` 事件，overlay 直接换 `src`，画面窗口不用刷新。

### 这只是辅助

循环播放一段录像**不等于**真人值守。平台真正看的是实时互动：
开麦隔几分钟说一句 > 画面里有张会动的脸 > 时钟和小窗。三者叠加才稳。

## 换直播背景

后台「直播背景」那一栏：上传一张图就换掉整块背景，**OBS 里不用重新加载源**。

以前背景写死在 `overlay/style.css` 的 `.poster` 里（`url("/overlay/assets/poster_clean.jpg")`），
换一次要改 CSS + 重启。现在链路是：

```
上传 -> 统一成 1080x1920（等比放大 + 居中裁切）-> poster_src.jpg（原图，留着）
     -> 可选：擦掉中间那块原有的字（pipeline/plate.py 的垂直渐变重建）
     -> poster_clean.jpg（真正铺上去的）
     -> ws 广播 background 事件 -> overlay 换 style.backgroundImage
```

三个必须知道的点：

1. **必须统一成 1080×1920**。写字的位置是按这个尺寸算死的（`wordsheet.place_box`
   和 overlay 里的字位），背景尺寸不一样，名字就会写偏。
2. **「擦掉原图上的字」只对同一套模板有用**。默认擦的框是 `229,1008 - 1058,1363`
   （原来「智纪元」的位置），换一张构图不同的海报就得自己填框，或者干脆关掉
   ——新背景本来就干净的话，勾了反而会在中间抹一条渐变带。
3. **每次上传都会把上一代成对备份**（`poster_clean.bak.jpg` + `poster_src.bak.jpg`），
   「恢复上一张」就是字节级还原。只留一代，再传一张就把上上一代顶掉。

> 换完背景，`data/signatures` 里那些**整张海报的成图还是旧背景**，空场回放时会闪一下。
> 想让画面统一，就在「图片管理」里清掉旧素材，或者让新单子重新生成。

### 写完那 3 秒的背景

收笔之后 overlay 会淡入一层 `.shot`（整张成图），停留 3 秒再写下一位。**这层图以前是
生成的时候就合成好落盘的**（`data/signatures/*_full.jpg`），所以换过背景之后，那 3 秒里
淡进来的是旧背景——观众会看到"背景跳了一下又跳回去"。

现在改成**每次播之前现合成**：`main._live_shot()` 拿当前 `poster_clean.jpg` 当底板，
把笔迹盖上去，写进固定的 `data/cache/live_shot.jpg`（不带 seq，避免播一晚上堆上千张 300KB），
靠 `?v=` 时间戳绕缓存。素材库回放（`provider=library`）走同一条路，所以空场循环也是新背景。

代价是每次播放多一次合成（JPEG 1080×1920，约 30~60ms），可以忽略。

改文件名而不是改内容是不行的——浏览器会缓存同名图片。所以后端给 URL 加了
`?v=时间戳`，overlay 连上来时也会主动 `GET /api/background` 要一次最新地址。

### 多张背景轮换（把"画面重复"拆开）

只换一张还是"每张都长一样"。后台「直播背景」里现在可以存**一组**背景
（`overlay/assets/backgrounds/`，索引在 `_index.json`），按"每写完 N 个名字换一张"自动换：

```
POST /api/background/add?name=春色&erase=0   body=原图   存进库（库里第一张会自动启用）
GET  /api/background/list                              库里有哪些、当前是哪张
POST /api/background/pick     {"id": "..."}            手动切到某一张
POST /api/background/remove   {"id": "..."}            从库里删一张
POST /api/background/rotate   {"rotate": true, "every": 6}   开关 + 换的节奏
```

切换时机只有一处：`producer` 的空场分支（`queue_library`）。那是"两张字之间"唯一的空档，
写到一半换底板，画面会闪一下，观众一眼看出是程序在切图。

三个约束/坑：

1. **必须是同一版式**。字位固定在 `193,851 - 893,1148`（1080×1920 坐标系），
   换色、换纹理、换四周装饰都行，构图换了字就写到别处去了。
2. **合成缓存靠文件名失效，不靠删**。`Library._full_view` 的输出名里带底板指纹
   （`mtime + 大小`），换背景等于换了一套新文件名，旧的自然读不到。
   以前是 `glob` 删 jpg——一张背景几十个文件，批量删会被系统的删除保护拦住
   （严重时直接杀进程），而且删完下一张还要重新合，没收益。
3. 库里不足 2 张时，开了轮换也不会动（没得换）。

## 后台管理空场素材（上传 / 删除）

空场循环播的是 `data/signatures` 里的成图。后台页面 <http://127.0.0.1:8850/admin/>
最下面那一栏「空场循环素材」就是它们的清单：

- **上传**：选图（可多选）→ `POST /api/library/upload`，原图直接放请求体，名字走 query。
  两种图都收，会自动抠出透明笔迹：
  * **整张海报**（背景 + 已写好的名字）：先缩到 1080×1920，再和底板 `poster_clean.jpg` 做差，
    分位数当"实心墨"强度算 alpha，再反预乘回纯墨色；
  * **白底只有字**（模板那种）：亮度算 alpha，**不缩放**——白底图常是很宽的一条，
    硬拉成竖版会把字放大到只剩一两笔（踩过这个坑）。
  存成 `up_MMDD_HHMMSS_<名字>_glyph.png` + `_full.jpg`（`_full` 是拿底板重新合的一张，
  所以后台缩略图、OBS 重连兜底看到的都是"背景 + 这个名字"）。
- **删除**：格子右上角 `×` → `POST /api/library/delete`，删掉两张图 + `data/cache/full` 里的合成缓存
  + `_library.json` 里那一项，然后 `refresh(True)` 立刻从轮播里消失。
- 列表 `GET /api/library` 的尺寸取自字框缓存，不读盘，所以后台 6 秒轮询一次也不费。
- 上传/删除都会写一条运行日志（`后台上传素材「张三」，素材库 46 张`），方便回查。

### 一键按当前样式补货（素材库被清空之后用）

空场有三层兜底：**素材库**（播现成成图）→ **虚拟名字池**（`app/virtual.py`，用**本地楷体**
起头）→ 什么都不播。所以把「图片管理」清空之后，空场会掉到第二层，写出来的字是**楷体**——
和后台选的「马善政 + 烫金」根本不是一回事，看起来像样式没生效。

补救不用一张张手动传：

> 后台「图片管理」→ 数量填 20 → **按当前样式生成空场素材**

`POST /api/library/generate` 会拿 `virtual.names` 里的名字，走**和真人单完全同一条**出图链路
（`sdcn.batch` / `doubaoweb.batch`），落成素材库认的那一对文件
（`ai_MMDD_HHMMSS_b1_名字_glyph.png` + `_full.jpg`），跑完自动 `refresh(True)`。

- **在后台任务里跑**，不挡直播；进度在按钮下面（`3/20（正在写「李雷」，失败 0）`），
  也可以看 `/api/admin/state` 的 `libgen`。
- 每张 2~3 秒，20 张约 1 分钟。名字池不够会循环取。
- 生成出来的 `_full.jpg` 用的是**当前背景**，所以和换背景那条链是自洽的。
- `provider` 是 `local` 时会直接报错（本地笔画出不了"成图"），先把签名样式切到 sdcn。

## 名字去重（同一个名字只写一遍）

直播间里「张三」被八个人报名是常态。以前只挡住"同一个昵称 + 同一个名字还在队列里"
这一种，实际会漏三种最常见的：不同人打同一个名字、名字正在写时又有人打、
写完一分钟同一个人再打一遍。

现在判定前先**归一化**：全角转半角、去掉所有空格、英文不分大小写，
所以「ＴＴ」「tt」「 T t 」是同一个名字。然后这三种情况都算重复，直接丢掉并记日志
（`@小怀念 弹幕「何小英」跳过：刚写过（32 秒前）`）：

| 情况 | 结果 |
|---|---|
| 排队中 | 拒绝，`已经在排队` |
| 正在写这一张 | 拒绝，`正在写这一张` |
| 窗口期内刚写完 | 拒绝，`刚写过（N 秒前）` |
| 同一个名字有人在队里，此时有人送礼 | **合并**到那张单上，升级成金片插队，不写两遍 |
| 送礼（窗口内已写过） | 默认允许再写一次（花了钱），`dedupe.gift_bypass: false` 可关掉 |

配置在 `config.yaml`：

```yaml
queue:
  dedupe:
    window: 1800        # 写完多少秒内不再重复写；0 = 关掉去重
    across: name        # name = 只要名字一样算重复 | user = 同一个人重复才算
    gift_bypass: true   # 礼物单是否绕过去重
```

两个例外：**空场回放**（幽灵单）和**手动补单**（`/api/simulate`、后台"加一单"）不走去重——
前者是循环播放素材库，后者是主播自己的手，本来就想再写一遍。

## 叠加层为什么这么排版

1080×1920 竖屏，就是一张海报：**背景是固定的底板，只有中间那行名字是 AI 写的**。

- `.poster` 是底板 `overlay/assets/poster_clean.jpg`，`.shot` 是"底板 + 这一单的名字"合成出来的成图。
  写的时候 `.shot` 藏着、露出底板 + 正在写的笔迹；收笔那一刻把 `.shot` 淡进来、再清掉画布。
  框外像素差只有 3/255，所以观众看到的是"字写完了"，而不是"换了张图"。
- **收笔之后停 3 秒**（`tiers[].hold_seconds`），这 3 秒是纯截图时间：overlay 不会立刻
  报完成，而是等 `.shot` 淡入彻底结束（200ms 抬笔 + 700ms 淡入）才发 `done`，
  后端从收到 `done` 开始才计时，所以停留期间画面已经是完整的成图，随时截都是成品。
- 队列**悬浮在右上角**（`top:28 right:40`，宽 330，**固定 8 行**）：表头「排队中 N 人」，
  每行 = 序号 + 名字 + 状态标签。行数由 `queue.panel_slots` 控制，永远满格——
  真人往上顶之后队尾会补虚拟观众，不会越排越短。
  这块面板实测高度 278，卡在海报那行说明字（y≈376）上面，不会压字。
- 面板是**三段合一**（`queue_view` 的 `panel` 字段，顺序就是显示顺序）：

  | 状态 | 数据来源 | 标签 | 样式 |
  |---|---|---|---|
  | 正在写 | `qm.current` | 正在写 | 金边 |
  | 出字中 | `qm.pending`（已交豆包、还没出图） | 出字中 | 压暗 |
  | 排队 | `qm.items` | 弹幕 / 礼物插队 | 礼物整行金片 |

  为什么要有「出字中」：单子一被 `pop_real` 取走去生成，就从 `items` 里消失了，
  豆包又要 25 秒才出图——只挂 `items` 的话，观众打完名字会在这 25 秒里从面板上凭空消失，
  以为没排上。`pending` 只在 `finish()` / 被删 / 被跳时才摘掉。
- **真人会往上顶，一直顶到第 1 行被写出来**：进队时他站在**面板最后一行**（第 8 行），
  前面那 7 位虚拟是真在播的；之后每播完一张幽灵，虚拟区就少一行，他往上移一格：
  **8 → 7 → … → 2 → 1**。顶到第 1 行，就是他开始被写出来的时刻。
  * 面板行数固定 `queue.panel_slots`（默认 8）。真人占了几行，虚拟区就让出几行，
    所以真人**永远看得见**——以前写死"8 行虚拟 + 真人第 9 行"，第九行掉在面板外面，
    观众打完名字在自己手机上看不到自己。
  * 他往上顶、队尾空出来的位置立刻拿新虚拟补满，面板永远满格（`queue_view` 末尾那段补位）。
  * 虚拟区行数 = `1 + GHOST_LEFT`（正在播的那张 + 还没播的几张），随 `GHOST_LEFT` 收；
  * 幽灵不够（素材库只有两三个名字）就从 `virtual.names` 补满，不会因为素材少而少顶几格；
  * 有真人排队期间虚拟区名字冻结（`_note_ghost` 不再改 GHOSTS），只收行、不换人，
    否则观众会觉得"上面的人在乱跳"；
  * 礼物不等位次，固定插在第 2 行。
  * 开播时直接从素材库名字 + `virtual.names` 垫满，不等回放慢慢攒（攒满 8 行要播 8 次，
    头几分钟面板会一格一格长出来，一眼假）。
  * **同名去重**：素材库只有三张图时，空场会循环回放，不去重面板就成了「张三 张三 张三」。
  * `SKIP_GHOST = {"张三","王小明"}`：这两个名字太像示例名，不当幽灵观众
    （素材库里有它们的成图照样能播）。
- **礼物固定占第 2 行**：`_to_front` 把新礼物插到 `items[0]`，所以面板上最新刷的那位
  永远站在第 2 行（第 1 行是正在写），前一个礼物顺延到第 3 行，仍然排在普通弹幕单前面。
  再有人刷，新礼物顶到第 2、前面的依次后移——这就是"当前写完就写礼物"的可视化。
  礼物多到塞满虚拟区时，溢出的顺延到真人区最前面，不会从面板上消失。
- **虚拟位次是真要走完的**（`queue.ghost_wait`，默认 8）：真人进队后，producer 先把
  素材库里的成图依次播 8 张，才生成并播放他的名字。每张约 8 秒运笔 + 3 秒展示，
  8 位大约 **80~90 秒**——"排在队尾就真等前面那些人"的代价。面板上看得见他每 10 秒
  往上顶一格。设 `0` 退回旧行为（幽灵只占面板位置，真人 2~3 秒出图）。
  * 礼物不等：`gift_waiting()` 一为真就把剩余位次清零，当前这张写完立刻写他。
  * 连续两个真人不会各等一轮：队列里有真人（`pending` 或 `current`）时，后到的只排在他后面。
  * 先报名字、过几秒才送礼：`add_gift` 会去 `pending` 里找同名那张**原地升级**，
    笔迹不重画，播放时按礼物档位重算书写时长。
- **队列比面板长时折成「…」+ 队尾一行**：`queue.panel_rows`（默认 12）控制最多画几行，
  超出部分压成 `… 还有 N 人在等`，最后单独挂一条**队尾**——队尾就是刚打完名字的那个人，
  他的序号就是他自己的排位。连刷礼物时队列能到二十几个，全渲染会把画面顶出去。
- 玩法说明是海鸥下面那条浅色玻璃条：「评论名字即可参与 · 送礼物插队」。
- 不再显示「本场已写 N 张」和最近完成记录——空场会循环重播，数字没有意义。
- 动画计时用 `performance.now()` 绝对时间，不是累加 dt。后台标签页被浏览器降频到 1fps 时，累加 dt 会把 6 秒的动画拖成几分钟。

## 一笔一划：毛笔是这么写出来的

写字这一段经历了三代：先是矢量描边（一眼电脑），再是"整张图从左往右揭开"（像扫描仪），
现在是**一支毛笔沿着笔顺走、墨跟着笔尖长出来**。

### 「笔已经走了，墨还没跟上」的三个原因（都修过，别改回去）

症状：写到一半有整段笔画是空的，收笔那一瞬间才全部出现。根因是**遮罩漏墨**，
而遮罩是"沿骨架刷一条有宽度的线"，骨架和墨水之间差了三处：

1. **笔顺必须从"显示的那张图"反推**，不能用没上材质的那份。材质会加投影/斜面/挤出，
   图更大、笔画更粗；拿窄的、错位的那份去画遮罩，边缘永远缺一圈。
   代价是投影会被当成笔画，所以上材质的图把 `alpha_min` 从 90 抬到 **190**
   （投影 alpha 约 115，被滤掉）。见 `main._ink_payload`。
2. **`MIN_LEN` 从 55 降到 30**。骨架细化到不了笔画最尖的那截，短段又容易被当成"碎笔"
   过滤掉——那些墨不在任何一笔的覆盖范围里，只能等最后整块填充。实测「王小明」有
   **9% 的字身从来没被揭开过**（王的两横左端、小的两点、明的一横），降到 30 后消失。
3. **遮罩膨胀 1.12 → 1.22，并在收笔处补一个半径=笔宽的圆**。覆盖率 91% → **98.8%**。
   遮罩比字宽是安全的：合成是 `image × mask`，不会露出字外面的东西。

剩下那 1% 是抗锯齿边缘，收尾那次 `fillRect` 补上，肉眼看不出来。
`ORDER_VER` 改到 3，老缓存（笔数偏少的那种）会自动重算。

后端 `pipeline/brush.py` 从 AI 抠出来的透明笔迹反推运笔路径：
alpha 阈值 → 开运算去飞白毛刺 → 闭运算补小缺口 → 骨架细化 → 过交叉点追踪
→ 丢短碎片、去重 → **按字数切字、字内再按偏旁切左右结构** → 每笔按走向定起笔端
→ 方向接得上的近邻合并 → 平滑精简 → 距离变换取每一点的笔画半径。
「李雷」出 20~22 笔（真人 20 笔），结果缓存进 `data/signatures/_writes.json`。

笔顺这块踩过的坑都记在这里，因为"写歪"和"写乱"是两回事：

- **方向不能按远近定**。原来每笔调头都看"哪端离上一笔近"，结果横画从右往左写、
  竖画从下往上写。现在只看这一笔自己的走向：竖直分量大（竖/撇/捺/点）从上起，
  几乎是横的从左起。
- **不按字数切，两个字会同时冒墨**。「林」和「晚」挨得很近，x 投影上一条全空的缝
  都没有，整幅被当成一个字排笔顺，写的时候左右两边一起出墨，一眼就是瞎写。
  现在按名字字数在最"墨少"的列上下刀。
- **字内还要按偏旁切**。左右结构的字（林、晚、明）如果只在字内就近落笔，写完左边
  一横会先跳到右半边去。这里用小波谷检测：某列墨量远低于平均就切开，先左后右；
  上下结构的字（李、雷）切不开，自然退回"就近落笔"。

前端 `draw.js` 的 `ink` 模式：
- `maskBuf` 累积"写到哪儿了"，一笔写完整条刷进去、永久保留；
- 当前这一笔按弧长推进，笔刷直径取 `ws`（局部笔画宽度），所以粗的地方露得宽、细的地方露得窄；
- 字形永远来自 AI 那版笔迹（`destination-in` 合成），我们只控制露出多少，怎么走都不走形；
- 墨比笔尖多露 `INK_LEAD = 7`（画布像素）。笔锋是一个"点"、笔画末端又飞白收细，
  正好齐平时屏幕上就是"笔尖悬在空白纸上"；让墨抢在笔尖前面一小段，笔锋才始终压在墨里；
- 两笔之间不是瞬移：`--lift` 把笔抬 16px，再从上一笔收笔处沿直线滑到下一笔起笔
  （smoothstep 缓入缓出，滑的路上抬着、落地压回纸面），所以笔一直是"贴着墨在动"；
- 全部写完后一帧把遮罩补满（骨架覆盖不到的飞白碎点），紧接着淡入成图，看不出来。

笔尖坐标（`penTo`）只认**未缩放**的布局值：`sand.offsetLeft + x * sand.offsetWidth / BOARD_W`。
早先用 `getBoundingClientRect()` 相减是错的——那拿到的是 stage 缩放后的视觉像素，
而 `left/top` 是 CSS 像素，窗口不是整 1080×1920 时位移会被放大 1/k 倍
（窗口 700×1244 时笔尖偏到 74px 外，看着就是"笔没在字上"）。

毛笔本身是纯 CSS 画的（`style.css` 的 `.brush`）：竹木笔杆 + 硬木笔斗 + 上宽下尖的笔毫，
笔尖钉在落笔点上，`transform-origin: 50% 100%` 绕笔尖旋转，`--s` 跟字框宽度缩放、
`--rot` 跟运笔方向微调倾角。UI（提示条、昵称、队列）层级压在笔上面，笔杆不会挡住字。

## 空场怎么办

**空场一次都不叫豆包**——直接播 `data/signatures` 里已经生成好的成图（`app/library.py`）。
开播、改配置重启、OBS 重连这些时刻都会触发空场，按"取个名字让 AI 画一张"走的话，
额度全烧在重复的"张三"上，还得干等二十秒才有第一个画面。

1. 扫一遍 `ai_*_full.jpg` + `ai_*_glyph.png`，配成「名字 / 笔迹 / 字框」一条记录；
2. 队列空了就按时间倒序轮播（`virtual.loop: cycle`），写的还是真笔迹，一样一笔一笔出来；
3. 真人弹幕进来 → 立刻插进去，照旧走豆包生成；写完之后回到素材库继续播。
4. 素材库是空的（全新环境还没出过图）→ 用本地字体写一个名字起头，免费、0.3 秒。

**开着 mock 挂机也不会烧额度**：`platform.type: mock` 是本机造出来的假观众，
事件带 `demo: True`，这些单只从素材库里找同名成图（找不到就本地笔画），
一次都不进豆包。启动日志里会写明"演示数据（mock）：假观众只说这 N 个名字"，
名字就是素材库里现成的那些，所以队列里喊「张三」就真的写出张三那张。

字框（笔迹该贴在哪儿）出图时只写进过内存，这里补回来：优先读
`data/signatures/_library.json` 缓存，缺了就用 `postercut.extract` 从原始成图重算一次
（0.3~1 秒/张，只在第一次启动发生），算完写回缓存。

```yaml
virtual:
  enabled: true
  library: true      # 关掉才回到"从名字池现生成"的老路子
  loop: cycle        # cycle=轮播已有成图 | repeat=一直播同一张
```

`virtual.enabled: false` 可以整块关掉。想看版式又不想排单，用
`PYTHONPATH=. python scripts/overlay_preview.py`（只跑 overlay，不排单不出图）。
